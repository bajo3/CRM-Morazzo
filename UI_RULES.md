# UI_RULES.md

## Estilo visual
- Sobrio, profesional y confiable.
- Base clara, alto contraste y foco en legibilidad.
- Evitar estetica recargada, dashboards ruidosos o decoracion innecesaria.
- Usar espaciado consistente y superficies limpias.
- La interfaz debe sentirse operativa, no publicitaria.

## Desktop first
- La prioridad es escritorio o notebook de mostrador.
- Resolver tablas, formularios y flujos para ancho amplio primero.
- En desktop, mostrar contexto suficiente sin obligar a navegar de mas.

## Mobile razonable
- No hace falta experiencia mobile compleja.
- Debe poder consultarse agenda, trabajos y datos clave.
- Formularios largos pueden apilarse verticalmente.
- Tablas densas deben tener alternativa compacta o scroll horizontal controlado.

## Jerarquia visual
- Titulos de pantalla claros y accion principal visible arriba.
- KPIs y totales destacados con peso visual moderado, sin exagerar.
- Estados, vencimientos y alertas deben diferenciarse rapido.
- Evitar mas de una accion primaria fuerte por seccion.

## Cards
- Usar cards para KPI, resumenes y bloques de formulario agrupados.
- Cards con padding consistente, borde sutil y titulo breve.
- No usar cards para fragmentar en exceso contenido que deberia convivir.

## Tablas
- Tablas para listados operativos: clientes, presupuestos, ordenes, stock, caja, agenda.
- Encabezados claros y columnas realmente utiles.
- Acciones por fila visibles pero discretas.
- Priorizar orden por fecha, estado o relevancia operativa.
- Permitir badges de estado y montos destacados sin saturar.

## Badges
- Badges simples, consistentes y de lectura rapida.
- Usar color con criterio semantico:
  - gris: borrador / pendiente / a coordinar
  - azul: enviado / agendado / en proceso
  - verde: aprobado / cobrado / terminado / realizado
  - amarillo: por vencer / saldo pendiente / stock bajo
  - rojo: rechazado / vencido / atrasado / rotura
- Nunca depender solo del color: incluir texto claro.

## Formularios
- Formularios rapidos, con labels visibles.
- Validaciones cercanas al campo y mensajes claros.
- Separar datos del cliente, detalle tecnico, pagos y notas en bloques.
- Inputs numericos con unidad visible cuando aplique.
- Usar defaults inteligentes donde sea seguro.

## Layout de pantallas
- Header de pagina con titulo, subtitulo breve y accion principal.
- Filtros arriba del listado cuando exista tabla.
- Panel lateral o modal solo si simplifica de verdad.
- Evitar anidar demasiadas secciones en una misma pantalla.

## PDFs
- Estetica prolija y profesional.
- Logo y datos del negocio arriba.
- Datos del cliente y fecha bien visibles.
- Tabla de detalle ordenada.
- Total final claramente destacado.
- No incluir observaciones internas.
